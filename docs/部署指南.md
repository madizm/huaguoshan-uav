# 花果山低空空域平台部署指南

本文依据当前仓库中的前端、认证入口服务、PostgREST、Nginx 配置和数据库脚本编写。目标拓扑遵循 ADR-0004/0005：Nginx 提供同源统一入口，认证入口服务签发 JWT，PostgREST 只暴露 `api` schema。

> 本仓库当前不是完整的“空库一键安装包”。数据库基础层依赖已安装的 3DCityDB 5.x、PostGIS、GEOVIS iBEST-DB 扩展，以及部分既有业务表。生产部署应优先从已验证数据库备份恢复，再执行本仓库的增量 SQL。

## 1. 部署拓扑

| 组件 | 默认监听 | 对外路径 | 说明 |
| --- | ---: | --- | --- |
| Nginx | `0.0.0.0:20000` | `/` | 统一入口 |
| 大屏 SPA | 静态文件 | `/` 或 `/lianyugang-uav/` | 来自 `deploy/dist.zip`，不是本仓库源码构建产物 |
| 三维工作台 | 静态文件 | `/frontend/tianditu-3d.html` | 当前仓库直接维护的 HTML/CSS/JS |
| 3D Tiles/DEM | 静态文件 | `/exports/` | 由导出脚本生成，不纳入 Git |
| 认证入口服务 | `127.0.0.1:13001` | `/auth/`、`/healthz` | `backend/auth_service.py` |
| PostgREST | `127.0.0.1:13000` | `/postgrest/` | 仅暴露 `api` schema |
| Scalar 文档 | 静态文件 | `/docs/` | `deploy/docs/index.html` |
| PostgreSQL | `5432` | 不对浏览器开放 | PostgreSQL 13.7 为当前已知环境版本 |
| 风险评估 worker | 无 HTTP 监听 | 不对外暴露 | `backend/risk_engine/worker.py`，异步评估侦测航迹并写入风险 current/history |

建议目录：

```text
/mnt/project/huaguoshan/       # 仓库发布目录
/etc/huaguoshan/               # 仅 root 可读的环境变量和 PostgREST 配置
/etc/systemd/system/            # 服务单元
```

## 2. 前置条件

服务器至少需要：

- Linux、Nginx、systemd。
- PostgreSQL 客户端；数据库服务可部署在独立主机。
- PostgREST。版本应先在预发布环境验证，配置项需支持 `db-schemas`、`db-anon-role` 和 `jwt-secret`。
- Python 3.12+ 和 `uv`。认证服务和风险 worker 使用 FastAPI、Uvicorn、psycopg、PyJWT、argon2-cffi 等依赖；离线包必须把风险 worker 依赖放入 wheelhouse。
- 数据库已安装 3DCityDB 5.x、PostGIS，以及项目实际使用的 `best_geomgrid`、`best_iot`、`best_geotrack` 等 iBEST-DB 扩展。
- 浏览器可访问 `https://api.tianditu.gov.cn` 与 `https://t{s}.tianditu.gov.cn`。完全离线环境必须另行镜像 Cesium/天地图资源并修改 `frontend/tianditu-3d.html` 和 `frontend/src/config/runtime-config.js`。

部署前检查数据库基础对象：

```bash
export DB_ADMIN_DSN='postgresql://<admin-user>:<password>@<db-host>:5432/<database>'
psql "$DB_ADMIN_DSN" -v ON_ERROR_STOP=1 <<'SQL'
select version();
select extname, extversion
from pg_extension
where extname in ('postgis', 'best_geomgrid', 'best_iot', 'best_geotrack')
order by extname;
select to_regnamespace('citydb') as citydb,
       to_regnamespace('airspace') as airspace,
       to_regnamespace('citydb_grid') as citydb_grid;
SQL
```

## 3. 发布文件

使用专用发布用户或 root 将仓库同步到目标目录。不要将 `.git`、开发凭据和本地缓存发布到 Web 可访问目录。

```bash
install -d -m 0755 /mnt/project/huaguoshan
rsync -a --delete \
  --exclude='.git/' \
  --exclude='.pi/' \
  --exclude='__pycache__/' \
  ./ /mnt/project/huaguoshan/
```

### 3.1 三维工作台

三维工作台无需 npm 构建，必须一起发布以下目录：

- `frontend/`
- `js/`
- `exports/`

`exports/` 已被 `.gitignore` 排除，必须从制品库、已验证服务器或数据生产任务单独同步。至少检查配置中启用的文件：

```bash
cd /mnt/project/huaguoshan
find exports -name tileset.json -print
```

当前 `runtime-config.js` 引用了建筑、花果山/连云港 DEM 以及 W/G 空域瓦片。缺失的 tileset 对应图层会加载失败，但不应影响其他图层。

### 3.2 大屏 SPA 制品

`deploy/dist.zip` 是外部构建制品，仓库中没有对应 `package.json`，因此不能在本仓库重建。其 `index.html` 使用绝对基路径 `/lianyugang-uav/`。若启用该 SPA，按以下布局解压：

```bash
cd /mnt/project/huaguoshan
rm -rf web/dist.next
mkdir -p web/dist.next/lianyugang-uav
unzip -q deploy/dist.zip -d /tmp/huaguoshan-dist
cp -a /tmp/huaguoshan-dist/dist/. web/dist.next/lianyugang-uav/
cp web/dist.next/lianyugang-uav/index.html web/dist.next/index.html
rm -rf /tmp/huaguoshan-dist
mv web/dist web/dist.previous 2>/dev/null || true
mv web/dist.next web/dist
```

这样 `/` 的首页和 `/lianyugang-uav/assets/...` 静态资源都能被现有 Nginx `root` 正确解析。发布完成并验收后再删除 `web/dist.previous`。

如果只部署当前仓库维护的三维工作台，可将 Nginx 的 `location /` 改为：

```nginx
location = / {
    return 302 /frontend/tianditu-3d.html;
}
```

同时保留配置中的 `/frontend/`、`/js/`、`/exports/`、`/auth/`、`/postgrest/` 和 `/docs/` location。

## 4. 数据库初始化与迁移

### 4.1 推荐方式：恢复基线后执行增量

先备份数据库：

```bash
pg_dump --format=custom --no-owner --file="huaguoshan_$(date +%Y%m%d_%H%M%S).dump" "$DB_ADMIN_DSN"
```

脚本普遍使用事务且大多可重复执行，但仓库没有迁移版本表。每次发布应记录执行的 Git commit 和 SQL 文件清单。

已存在完整 `citydb`、`airspace`、`terrain`、`citydb_grid` 基线时，建议顺序如下：

```bash

# 1. 最小角色引导。业务 SQL 中的授权语句要求 admin 已存在。
psql "$DB_ADMIN_DSN" -v ON_ERROR_STOP=1 <<'SQL'
do $$
begin
  if not exists (select 1 from pg_roles where rolname = 'admin') then
    create role admin nologin;
  end if;
  if not exists (select 1 from pg_roles where rolname = 'anonymous') then
    create role anonymous nologin;
  end if;
  if not exists (select 1 from pg_roles where rolname = 'authenticator') then
    create role authenticator login noinherit password '<temporary-random-password>';
  end if;
end
$$;
grant admin, anonymous to authenticator;
create schema if not exists api;
SQL

# 2. 认证凭据存储和受限数据库账号。
psql "$DB_ADMIN_DSN" -v ON_ERROR_STOP=1 -f backend/create_auth_credentials.sql
```

### 4.2 创建初始管理员

先用管理员连接执行 `create_auth_credentials.sql`，然后使用认证服务的受限数据库账号创建平台管理员：

```bash
export AUTH_DATABASE_DSN='postgresql://auth_service:<strong-db-password>@<db-host>:5432/<database>'
cd /mnt/project/huaguoshan
uv run scripts/create_initial_admin.py --username admin
```

脚本交互读取至少 12 位密码并存储 Argon2id 哈希。不要把平台密码放入命令行、Git 或 systemd unit。

仓库 SQL 中的 `authenticator`、`auth_service` 默认密码和 `pgrest.conf` 的 JWT secret 都是开发占位值。生产上线前必须修改数据库角色密码，并让服务配置保持一致：

```sql
alter role authenticator password '<strong-random-password>';
alter role auth_service password '<strong-random-password>';
```

## 5. PostgREST

不要直接使用仓库根目录的 `pgrest.conf` 上生产，其中包含开发数据库地址和开发 JWT secret。创建 `/etc/huaguoshan/postgrest.conf`：

```ini
db-uri = "postgres://authenticator:<strong-db-password>@<db-host>:5432/<database>"
db-schemas = "api"
db-anon-role = "anonymous"
jwt-secret = "<at-least-32-byte-random-secret>"
server-host = "127.0.0.1"
server-port = 13000
```

生成 JWT secret 示例：

```bash
openssl rand -base64 48
```

创建 `/etc/systemd/system/huaguoshan-postgrest.service`：

```ini
[Unit]
Description=Huaguoshan PostgREST
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=huaguoshan
Group=huaguoshan
ExecStart=/usr/local/bin/postgrest /etc/huaguoshan/postgrest.conf
Restart=on-failure
RestartSec=3
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

`ExecStart` 应改成目标机 `command -v postgrest` 的实际路径。

## 6. 认证入口服务

创建 `/etc/huaguoshan/auth.env`，权限必须为 `0600`：

```dotenv
AUTH_DATABASE_DSN=postgresql://auth_service:<strong-db-password>@<db-host>:5432/<database>
PGRST_JWT_SECRET=<与 PostgREST jwt-secret 完全相同>
AUTH_JWT_ISSUER=huaguoshan-uav-auth
AUTH_TOKEN_TTL_SECONDS=900
AUTH_SERVICE_HOST=127.0.0.1
AUTH_SERVICE_PORT=13001
AUTH_SCHEMA=auth
```

```bash
chown root:root /etc/huaguoshan/auth.env
chmod 0600 /etc/huaguoshan/auth.env
```

创建 `/etc/systemd/system/huaguoshan-auth.service`：

```ini
[Unit]
Description=Huaguoshan Authentication Entry Service
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=huaguoshan
Group=huaguoshan
WorkingDirectory=/mnt/project/huaguoshan/backend
EnvironmentFile=/etc/huaguoshan/auth.env
ExecStart=/usr/local/bin/uv run auth_service.py
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

`ExecStart` 应改成目标机 `command -v uv` 的实际路径。首次启动需要下载 Python 依赖；内网环境应提前准备 uv 缓存或内部 Python 包镜像。

## 7. 风险评估 worker

风险评估服务是无 HTTP 监听的后台 worker。它消费已建立航迹的目标观测，读取已发布防御圈和评分规则，将结果写入 `event_response.target_risk_assessment`、`event_response.target_risk_current` 和 `situation.change_event`。它不调用任何反制或打击设备。

生产环境应为 worker 使用独立的 `risk_engine` 登录角色，不要复用 `postgres`、`admin` 或侦测接入账号。迁移 `backend/create_target_risk_assessment.sql` 会创建该角色及最小表权限；部署时由密钥系统设置密码：

```sql
alter role risk_engine password '<strong-random-password>';
```

创建 `/etc/huaguoshan/risk-engine.env`，权限设为 `0600`：

```dotenv
RISK_ENGINE_DATABASE_URL=postgresql://risk_engine:<strong-db-password>@<db-host>:5432/<database>
RISK_ENGINE_WORKER_NAME=defense-assessment
RISK_ENGINE_BATCH_SIZE=100
RISK_ENGINE_POLL_INTERVAL=1
RISK_ENGINE_LOG_LEVEL=INFO
```

创建 `/etc/systemd/system/huaguoshan-risk-engine.service`：

```ini
[Unit]
Description=Huaguoshan Detection Risk Assessment Worker
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple
User=huaguoshan
Group=huaguoshan
WorkingDirectory=/mnt/project/huaguoshan
EnvironmentFile=/etc/huaguoshan/risk-engine.env
ExecStart=/opt/huaguoshan/runtime/bin/python -m backend.risk_engine.worker --database-url ${RISK_ENGINE_DATABASE_URL} --worker-name ${RISK_ENGINE_WORKER_NAME} --batch-size ${RISK_ENGINE_BATCH_SIZE} --poll-interval ${RISK_ENGINE_POLL_INTERVAL}
Restart=always
RestartSec=5
KillSignal=SIGTERM
TimeoutStopSec=30
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

启停和检查：

```bash
systemctl daemon-reload
systemctl enable --now huaguoshan-risk-engine
systemctl status huaguoshan-risk-engine --no-pager
journalctl -u huaguoshan-risk-engine -f
```

worker 没有 `/healthz` 网络端点；以 systemd 状态、日志、`risk_worker_cursor` 推进和态势接口中的 `riskAssessment` 作为运行检查。单批排障可执行：

```bash
sudo -u huaguoshan /opt/huaguoshan/runtime/bin/python -m backend.risk_engine.worker --database-url "$RISK_ENGINE_DATABASE_URL" --once --batch-size 100
```

如果数据库尚未完成风险评估迁移，worker 不应启动；迁移成功后再启动并观察游标是否推进。`RISK_ENGINE_BATCH_SIZE` 应为 1 至 1000，轮询间隔不低于 0.1 秒。

## 8. Nginx

仓库配置固定使用 `/mnt/project/huaguoshan`、端口 `20000`、认证端口 `13001` 和 PostgREST 端口 `13000`。部署路径或端口不同必须先修改。

可直接使用完整独立配置：

```bash
cp /mnt/project/huaguoshan/deploy/nginx.conf /etc/nginx/nginx.conf
nginx -t
systemctl reload nginx
```

若服务器已有共享 Nginx，不要覆盖主配置，应将 `deploy/nginx.conf` 中的 `upstream` 和 `server` 内容适配后放入站点配置。必须保留 `/exports/` 路由，否则三维工作台的 3D Tiles/DEM 请求会错误落入 SPA 根目录。

生产环境建议在 Nginx 前配置 HTTPS，只对外开放 `80/443` 或批准的 `20000`，不要对外开放 `13000`、`13001` 和数据库端口。若经外层反向代理挂载到子路径，必须同时验证 SPA 的 `/lianyugang-uav/` 基路径以及三维工作台的相对 `/auth`、`/postgrest`、`/exports` 路径。

## 11. 回滚与备份

应用静态文件回滚：将 `/mnt/project/huaguoshan` 切回上一发布目录，或将 `web/dist.previous` 恢复为 `web/dist`，然后执行 `nginx -t && systemctl reload nginx`。

服务代码回滚：切回上一已验证 Git commit，重启认证服务；PostgREST 本身通常无需因前端回滚而降级。

数据库回滚：当前 SQL 没有对应 down migrations。执行 SQL 前必须做 `pg_dump --format=custom` 备份；涉及表结构和权限的失败回滚应从备份恢复到新库并切换连接，不建议在生产库手工猜测逆向 SQL。

至少备份：

- PostgreSQL 全库或相关 schemas：`auth`、`api`、`airspace`、`citydb`、`citydb_grid`、`terrain`、`flight_path`、`flight_plan`、`equipment`、`emergency_resource`、`raw`。
- `/etc/huaguoshan/` 配置，但应进入加密备份且限制访问。
- `exports/` 生成制品及其生成参数。
- 对应发布 Git commit 和外部 `dist.zip` 的校验和。

## 12. 常见故障

| 现象 | 优先检查 |
| --- | --- |
| `/healthz` 为 502 | `huaguoshan-auth` 状态、端口是否为 13001、数据库 DSN 是否可达 |
| 登录成功但 API 返回 401 | 认证服务与 PostgREST 的 JWT secret 是否逐字一致，JWT `role` 是否为 `admin` |
| API 返回 42501/403 | `authenticator` 是否拥有 `admin`，`admin` 是否获得 `api` 对象授权 |
| PostgREST 报 schema cache 错误 | 执行 `notify pgrst, 'reload schema'`，检查 SQL 是否完整成功 |
| 3D Tiles/DEM 返回 404 | `exports/` 是否已同步、Nginx 是否有 `/exports/` location、配置路径大小写是否一致 |
| SPA 首页正常但 JS/CSS 404 | 制品是否按 `/lianyugang-uav/` 基路径布局，而不是只解压到 `web/dist/assets` |
| Cesium 空白或天地图失败 | 浏览器能否访问天地图域名、Token 是否有效、HTTPS 页面是否加载 HTTP 资源 |
| 原始源数据 RPC 执行失败 | `raw` 三张源表及字段是否存在，是否误在不含真实源数据的库执行该脚本 |

## 13. 上线前安全清单

- 更换仓库示例中的数据库密码、JWT secret 和平台管理员密码。
- 不把 `开发环境.md`、`生产环境.md`、`.env`、数据库备份暴露给 Nginx。
- 数据库、PostgREST、认证入口服务仅允许本机或受控网络访问。
- 启用 HTTPS，并由外层代理传递正确的 `X-Forwarded-*` 头。
- 限制 `/docs/` 的网络访问范围；门户本身可匿名打开，登录后会读取带权限的 PostgREST OpenAPI。
- 对 Nginx、认证失败、数据库连接耗尽和磁盘空间配置监控告警。
- 记录 3D Tiles、DEM 和数据库数据版本，保证静态空间制品可追溯。
