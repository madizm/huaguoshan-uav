# 云平台侦测数据接入：数据库与系统内部接口设计

## 1. 目标与范围

本文设计用于接入云平台站点 `stationId=90` 的雷达和电侦数据，并为系统内部的态势展示、目标航迹、事件判定和历史回放提供稳定接口。

> 实施说明：当前版本已通过 `backend/create_detection_situation_schema.sql` 和 `scripts/radar_cloud_connector.py` 落地。第 6 章的 HTTP 路径表示逻辑内部接口；当前连接器直接调用同语义的受限 PostgreSQL 函数，未增加透传 HTTP 服务。具体运行方式见 `docs/api/detection-situation-api.md`。

设计遵循以下边界：

- `sourceType=10` 表示雷达，`sourceType=20` 表示电侦。
- 云平台厂商字段只存在于接入适配层和原始载荷中，不直接成为核心业务接口。
- 复用现有 `equipment.asset`、`equipment.asset_status_current` 和 `equipment.raw_observation`，不重复建设设备台账和通用原始观测表。
- 原始观测追加写入，不更新、不删除；当前目标和航迹是可更新的融合判断。
- 第一阶段只接收侦测、状态和离线事件，不提供转台、雷达开关、功放、打击等真实控制接口。
- 系统内部统一使用 WGS84（EPSG:4326）、米、米/秒、度和 `timestamptz`。

## 2. 已验证的来源特征

实际联调结果对数据模型有以下约束：

1. 在线列表正确地址是 `GET /uav/onlineList?stationId=90`；文档中的 `/api/uav/onlineList` 实际返回 404。
2. 在线列表响应当前不包含 `sourceType`，不能靠序列号或型号可靠推断雷达/电侦。
3. WebSocket 消息中的目标记录包含 `sourceType`。
4. `uav_dashboard_snapshot.payload.list` 可能混合多个站点；外层 `payload.stationId` 不能作为列表内所有目标的站点标识。
5. 必须按每条记录的 `item.stationId` 过滤和入库。
6. 电侦可以只有频率和型号，没有目标经纬度；这仍是一条有效观测，但不能更新空间航迹位置。
7. `azimuth` 是目标相对站点的方位角，不是目标航向。
8. `distance` 单位为千米，入库时转换为米。
9. 来源时间没有时区，接入配置必须显式指定 `Asia/Shanghai`，转换为 `timestamptz` 后仍保留原始载荷。

## 3. 总体数据流

```text
云平台 HTTP 在线列表 + WebSocket
  -> 云平台适配器
  -> 侦测接入模块
     -> 设备状态更新
     -> equipment.raw_observation（原始证据）
     -> situation.target_observation（目标观测语义）
     -> situation.source_target_session（来源会话）
     -> situation.airspace_target / target_track（当前融合判断）
     -> situation.change_event（增量游标）
  -> api 态势快照 / 航迹详情 / 增量接口
  -> 前端展示与事件判定
```

启动或重连顺序：

1. 连接 WebSocket，先开始缓冲实时消息。
2. 调用在线列表，写入当前在线目标；因其缺少 `sourceType`，来源类型暂存为未知。
3. 处理缓冲的 WebSocket 消息，以带 `sourceType` 的实时数据补齐来源类型。
4. 持续消费 WebSocket；断线期间通过在线列表重新对账。

这个顺序避免“先拉快照、后连 WebSocket”造成窗口期消息丢失。

## 4. 数据模型

建议新增 `situation` schema。`equipment` 表达设备和原始证据，`situation` 表达空域目标、来源会话和航迹。

### 4.1 来源类型字典 `situation.detection_source_type`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `vendor_code` | smallint | PK | 厂商 `sourceType` |
| `code` | text | UNIQUE, NOT NULL | 内部稳定编码 |
| `name` | text | NOT NULL | 中文名称 |
| `enabled` | boolean | NOT NULL DEFAULT true | 是否接收该类型 |
| `description` | text |  | 类型说明 |

初始字典：

| vendor_code | code | name |
|---:|---|---|
| 10 | `radar` | 雷达 |
| 20 | `radio_detection` | 电侦 |

未知来源不使用伪造数值。在线列表缺少 `sourceType` 时，观测的 `source_type_code` 保存为 `NULL`，待实时消息或后续对账补充。原始观测本身保持不可变；补充结果记录在来源会话和融合关联中。

### 4.2 观测来源 `situation.observation_source`

观测来源是外部站点/盒子接入身份，不等同于具体雷达设备。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigserial | PK | 内部主键 |
| `source_system` | text | NOT NULL | 来源系统，如 `radar_cloud` |
| `external_station_id` | text | NOT NULL | 厂商站点 ID，如 `90` |
| `external_box_code` | text | NOT NULL DEFAULT '' | 盒子编码；未知时为空字符串 |
| `asset_id` | bigint | FK `equipment.asset(id)`, NOT NULL | 对应统一设备资产，通常为边缘盒子/反无综合设备 |
| `name` | text | NOT NULL | 来源显示名称 |
| `source_timezone` | text | NOT NULL DEFAULT `Asia/Shanghai` | 无时区来源时间的解释时区 |
| `coordinate_system` | text | NOT NULL DEFAULT `WGS84` | 来源坐标系 |
| `enabled` | boolean | NOT NULL DEFAULT true | 是否启用接入 |
| `metadata` | jsonb | NOT NULL DEFAULT `{}` | 厂商扩展配置，不保存密钥 |
| `created_at` | timestamptz | NOT NULL DEFAULT now() | 创建时间 |
| `updated_at` | timestamptz | NOT NULL DEFAULT now() | 更新时间 |

唯一约束：

```text
(source_system, external_station_id, external_box_code)
```

站点 90 当前建议映射：

```text
source_system       = radar_cloud
external_station_id = 90
external_box_code   = b260705174118582
asset_id            = 对应 equipment.asset.id
```

如能够取得具体雷达或电侦设备身份，在 `equipment.asset` 分别登记为 `microwave_radar`、`aoa_direction_finder` 或其他准确类别；不要仅根据 `sourceType` 虚构物理设备。

### 4.2.1 观测来源当前状态 `situation.observation_source_status_current`

该表记录接入链路状态，不把“云平台 WebSocket 已连接”等同于物理雷达在线。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `observation_source_id` | bigint | PK, FK `observation_source(id)` | 观测来源 |
| `connector_state` | text | NOT NULL | `connected`、`disconnected`、`degraded`、`unknown` |
| `last_connected_at` | timestamptz | NULL | 最近连接成功时间 |
| `last_disconnected_at` | timestamptz | NULL | 最近断开时间 |
| `last_message_at` | timestamptz | NULL | 最近收到合法消息时间 |
| `last_snapshot_at` | timestamptz | NULL | 最近在线列表对账时间 |
| `last_error_code` | text | NULL | 最近错误编码，不保存敏感详情 |
| `last_error_at` | timestamptz | NULL | 最近错误时间 |
| `updated_at` | timestamptz | NOT NULL DEFAULT now() | 更新时间 |

连接器状态变化写入 `situation.change_event`。物理盒子和雷达的在线信息仍分别写入 `equipment.asset_status_current`，两者不能互相替代。

### 4.2.2 `config_status` 设备遥测

`config_status` 是设备遥测，不是目标观测，不写入 `raw_observation`、目标会话或航迹。其存储分为：

- `equipment.counter_uas_telemetry_current`：保留每台反无综合设备最新完整规范化快照；
- `equipment.counter_uas_status_event`：仅在无人值守、子系统在线、旋转、启用频段等离散状态变化时追加；
- `equipment.counter_uas_telemetry_sample`：电压、电流、功率、温度、方位角等连续量最多每 60 秒采样一条；
- `equipment.asset_status_current`：同步盒子在线状态和心跳，但心跳刷新不重复生成通用状态历史。

协议没有提供状态采集时间，平台以接收时间同时作为 `observed_at`，并写入 `missing_source_time` 质量标记。雷达序列号仅用于关联已经登记的独立雷达资产；状态消息不能自动创建设备台账。

### 4.3 原始观测 `equipment.raw_observation`（复用）

每条 `uav_online_upsert`、快照列表项和离线事件都先形成原始观测。现有字段继续使用：

- `asset_id`：观测来源对应的盒子资产。
- `source_system`：`radar_cloud`。
- `source_observation_id`：接入模块生成的确定性幂等键。
- `observation_type`：`target_upsert`、`target_snapshot` 或 `target_remove`。
- `observed_at`：来源时间转换后的时间；来源未给时间时使用接收时间并标记质量问题。
- `received_at`：平台接收时间。
- `geom`：有合法经纬度时写 WGS84 Point，否则为 `NULL`。
- `height_amsl_m`：仅写来源 `altitude`；不得用相对高度 `height` 替代。
- `raw_payload`：完整的单条目标载荷，并附接入信封信息。
- `processing_status`：`received`、`normalized`、`rejected` 或 `needs_review`。

建议在 `raw_payload._ingest` 中附加：

```json
{
  "channel": "websocket",
  "messageType": "uav_dashboard_snapshot",
  "envelopeStationId": 30,
  "itemStationId": 90,
  "payloadHash": "sha256:...",
  "adapterVersion": "radar-cloud-v1"
}
```

幂等键建议由以下内容生成 SHA-256：

```text
source_system | item.stationId | sourceType-or-unknown | serial |
event_type | source_observed_at-or-received_bucket | canonical_payload_hash
```

不能只使用 `serial + currentTime`：同一秒内可能有频率或位置不同的有效观测。

### 4.4 目标观测扩展 `situation.target_observation`

该表与 `equipment.raw_observation` 一对一，只保存目标侦测领域字段，不重复保存原始 JSON、位置和 AMSL 高度。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `observation_id` | bigint | PK, FK `equipment.raw_observation(id)` | 原始观测 ID |
| `observation_source_id` | bigint | FK, NOT NULL | 观测来源 |
| `source_type_code` | smallint | FK `detection_source_type(vendor_code)`, NULL | 10 雷达、20 电侦；快照缺失时为空 |
| `producer_asset_id` | bigint | FK `equipment.asset(id)`, NULL | 能明确识别时的实际雷达/电侦设备 |
| `source_target_id` | text | NOT NULL | 厂商目标标识，当前取 `serial` |
| `source_session_id` | text | NULL | 厂商会话 ID，如 `sessionId` |
| `event_type` | text | NOT NULL | `online_upsert`、`snapshot`、`offline_remove` |
| `model` | text | NULL | 厂商识别的目标型号 |
| `frequency_mhz` | numeric | NULL | 侦测频率，MHz |
| `relative_height_m` | numeric | NULL | 来源 `height`，仅作为来源相对高度 |
| `horizontal_distance_m` | numeric | NULL, >= 0 | 来源 `distance` 转米 |
| `azimuth_deg` | numeric | NULL, 0-360 | 目标相对站点方位角 |
| `elevation_deg` | numeric | NULL, -90 至 90 | 目标相对站点俯仰角 |
| `speed_mps` | numeric | NULL, >= 0 | 来源 `directSpeed` 解析值 |
| `list_type` | smallint | NULL | 厂商名单类型原值 |
| `pilot_geom` | geometry(Point,4326) | NULL | 飞手位置；非法或空字符串不写 |
| `home_geom` | geometry(Point,4326) | NULL | 起飞点位置 |
| `quality_flags` | text[] | NOT NULL DEFAULT `{}` | 如 `missing_source_type`、`missing_position` |

约束：

- `event_type` 限定为三个内部枚举。
- `source_type_code` 未知时必须包含 `missing_source_type`。
- 位置有效性以关联的 `raw_observation.geom` 是否为空为准。
- 离线事件允许没有位置、频率、型号和高度。

索引：

```text
(observation_source_id, source_target_id, observation_id DESC)
(source_type_code, observation_id DESC)
(producer_asset_id, observation_id DESC)
GIN (quality_flags)
```

### 4.5 来源目标会话 `situation.source_target_session`

来源会话用于表达某个厂商目标从上线到离线的一次连续发现过程。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigserial | PK | 会话主键 |
| `observation_source_id` | bigint | FK, NOT NULL | 观测来源 |
| `source_type_code` | smallint | FK, NULL | 当前已知来源类型 |
| `source_target_id` | text | NOT NULL | 厂商目标 ID |
| `source_session_id` | text | NULL | 厂商会话 ID |
| `session_key` | text | NOT NULL | 厂商会话 ID 或平台生成键 |
| `state` | text | NOT NULL | `active`、`lost`、`closed` |
| `started_at` | timestamptz | NOT NULL | 首次发现时间 |
| `last_observed_at` | timestamptz | NOT NULL | 最近观测时间 |
| `ended_at` | timestamptz | NULL | 结束时间 |
| `end_reason` | text | NULL | `source_remove`、`timeout`、`reconciled_absent` |
| `current_observation_id` | bigint | FK `raw_observation(id)` | 最新观测 |
| `version` | bigint | NOT NULL DEFAULT 1 | 乐观并发版本 |

唯一约束：

```text
(observation_source_id, session_key)
```

没有厂商 `sessionId` 时：

- 首次 upsert/snapshot 创建平台会话键。
- 30 秒无新消息标记为 `lost`。
- 收到 `uav_online_remove` 标记为 `closed`。
- 已结束后再次出现同一 `serial`，创建新会话，不能复用旧航迹。

### 4.6 空域目标 `situation.airspace_target`

空域目标是平台当前可信解释，不是设备资产，也不是一条原始报文。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigserial | PK | 目标主键 |
| `target_code` | text | UNIQUE, NOT NULL | 内部稳定目标编码 |
| `target_class` | text | NOT NULL DEFAULT `unknown` | `uav`、`bird`、`unknown` 等 |
| `display_name` | text | NULL | 展示名称 |
| `identity_status` | text | NOT NULL DEFAULT `unverified` | `unverified`、`identified`、`conflicted` |
| `confidence` | numeric | NULL, 0-1 | 当前身份置信度 |
| `first_observed_at` | timestamptz | NOT NULL | 首次发现时间 |
| `last_observed_at` | timestamptz | NOT NULL | 最近发现时间 |
| `active` | boolean | NOT NULL DEFAULT true | 是否为当前活动目标 |
| `metadata` | jsonb | NOT NULL DEFAULT `{}` | 融合扩展信息 |
| `created_at` | timestamptz | NOT NULL DEFAULT now() | 创建时间 |
| `updated_at` | timestamptz | NOT NULL DEFAULT now() | 更新时间 |

第一阶段不做跨来源自动融合：一个来源会话默认建立一个空域目标。后续确认雷达和电侦指向同一飞行器时，可将多个来源会话关联到同一目标，并保留融合证据和冲突信息。

### 4.7 目标航迹 `situation.target_track`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigserial | PK | 航迹主键 |
| `track_code` | text | UNIQUE, NOT NULL | 内部稳定航迹编码 |
| `target_id` | bigint | FK `airspace_target(id)`, NOT NULL | 所属空域目标 |
| `source_session_id` | bigint | FK, NULL | 第一阶段对应的来源会话 |
| `status` | text | NOT NULL | `tracking`、`lost`、`closed` |
| `first_observed_at` | timestamptz | NOT NULL | 首个观测时间 |
| `last_observed_at` | timestamptz | NOT NULL | 最新观测时间 |
| `lost_at` | timestamptz | NULL | 丢失时间 |
| `current_observation_id` | bigint | FK `raw_observation(id)` | 最新有效位置观测 |
| `track_confidence` | numeric | NULL, 0-1 | 航迹可信度 |
| `version` | bigint | NOT NULL DEFAULT 1 | 乐观并发版本 |
| `updated_at` | timestamptz | NOT NULL DEFAULT now() | 更新时间 |

第一阶段约束 `source_session_id UNIQUE`。没有坐标的电侦观测可以更新目标“最近被发现”时间和证据，但不能覆盖 `current_observation_id` 中已有的有效空间位置。

### 4.8 航迹观测关联 `situation.track_observation`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `track_id` | bigint | FK, NOT NULL | 航迹 ID |
| `observation_id` | bigint | FK `raw_observation(id)`, UNIQUE | 观测 ID |
| `association_method` | text | NOT NULL | `source_session`、`manual`、`fused` |
| `association_confidence` | numeric | NULL, 0-1 | 关联置信度 |
| `associated_at` | timestamptz | NOT NULL DEFAULT now() | 关联时间 |

主键为 `(track_id, observation_id)`。该表使航迹历史可以关联雷达、电侦和后续光电证据，而不覆盖任何原始观测。

### 4.9 增量变更事件 `situation.change_event`

该表不是业务空域事件，而是内部读模型增量游标。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | bigserial | PK | 单调递增游标 |
| `event_type` | text | NOT NULL | `target_upsert`、`target_remove`、`source_status` |
| `aggregate_type` | text | NOT NULL | `target_track`、`observation_source` |
| `aggregate_id` | bigint | NOT NULL | 聚合对象 ID |
| `observation_source_id` | bigint | FK, NULL | 观测来源 |
| `occurred_at` | timestamptz | NOT NULL | 业务发生时间 |
| `payload` | jsonb | NOT NULL | 内部稳定事件载荷 |
| `created_at` | timestamptz | NOT NULL DEFAULT now() | 入库时间 |

索引：

```text
(id)
(observation_source_id, id)
(created_at)
```

建议保留 7 天。前端轮询和未来 WebSocket 网关读取同一游标，重连时可以补发，不依赖 PostgreSQL `NOTIFY` 的瞬时消息。

## 5. 关键关系

```text
equipment.asset
  1 -> N equipment.raw_observation
  1 -> N situation.observation_source

situation.observation_source
  1 -> 1 situation.observation_source_status_current
  1 -> N situation.target_observation
  1 -> N situation.source_target_session

situation.target_observation
  1 -> 1 equipment.raw_observation

situation.source_target_session
  1 -> 1 situation.target_track（第一阶段）

situation.airspace_target
  1 -> N situation.target_track

situation.target_track
  N <-> N target observations（通过 track_observation）
```

## 6. 接入模块内部接口

### 6.1 接收厂商消息

> 当前实现已将厂商报文解析、批次拆分、站点过滤、时区和单位转换移入 `RadarCloudAdapter`。数据库不再接收本节所示的厂商信封，而是由连接器逐条调用 `situation.ingest_target_observation(jsonb)` 写入 `schemaVersion=1` 的规范目标观测。以下 HTTP 信封仅保留为未来增加内部网关时的候选外层协议。

```http
POST /internal/v1/detection/messages
Authorization: Bearer <service-token>
Content-Type: application/json
Idempotency-Key: <optional-caller-key>
```

请求：

```json
{
  "sourceSystem": "radar_cloud",
  "channel": "websocket",
  "messageType": "uav_dashboard_snapshot",
  "receivedAt": "2026-09-20T09:46:08.900Z",
  "payload": {
    "list": [],
    "count": 0,
    "stationId": 30
  }
}
```

`messageType` 支持：

- `online_list_snapshot`：HTTP 在线列表结果。
- `uav_online_upsert`。
- `uav_dashboard_snapshot`。
- `uav_online_remove`。
- `config_status`。

返回：

```json
{
  "messageId": "sha256:...",
  "status": "accepted",
  "receivedItems": 5,
  "acceptedItems": 2,
  "duplicateItems": 1,
  "ignoredItems": 2,
  "rejectedItems": 0,
  "observationIds": [120031, 120032],
  "changeCursor": 8931,
  "warnings": [
    {
      "code": "envelope_station_mismatch",
      "message": "列表包含与外层 stationId 不同的目标，已按目标 stationId 分流"
    }
  ]
}
```

接口语义：

- 整个消息先完成 JSON 结构校验，再逐项处理。
- 单个坏数据不阻塞同批其他目标；逐项错误进入 `warnings/rejections`。
- 完全相同的重复消息返回成功，不产生重复观测和变更事件。
- 数据库事务内同时完成原始观测、会话、航迹和变更游标写入。
- 该接口只允许接入服务身份调用，不向浏览器和第三方公开。

### 6.2 接入连接状态


```json
  "observedAt": "2026-09-20T09:46:08.900Z",
  "lastMessageAt": "2026-09-20T09:46:08.412Z",
```

### 7.2 增量变化

```http
POST /postgrest/rpc/get_detection_situation_changes
```

请求：

```json
{
  "p_after_cursor": 8931,
  "p_station_ids": ["90"],
  "p_limit": 500
}
```

返回：

```json
{
  "from_cursor": 8931,
  "next_cursor": 8940,
  "has_more": false,
  "changes": [
    {
      "cursor": 8932,
      "type": "target_upsert",
      "occurred_at": "2026-09-20T09:46:13Z",
      "target": {}
    }
  ]
}
```

客户端规则：

- 首次调用快照并保存 `cursor`。
- 每 1 秒读取该游标之后的变化。
- `has_more=true` 时立即继续读取，不能跳到最新游标。
- 游标已超过保留期时返回 `409 cursor_expired`，客户端重新拉快照。

未来如增加内部 WebSocket，只需让网关读取同一 `change_event`，对外消息格式保持不变。

## 8. 字段映射

| 厂商字段 | 内部字段 | 规则 |
|---|---|---|
| `stationId` | `external_station_id` | 使用每条目标记录中的值 |
| `sourceType` | `source_type_code` | 10 雷达、20 电侦；缺失时为空 |
| `serial` | `source_target_id` | 不作为全局目标 ID |
| `sessionId` | `source_session_id` | 有值时优先作为来源会话键 |
| `currentTime` / `lastTime` | `observed_at` | 按来源时区转换为 `timestamptz` |
| `lng`, `lat` / `gps` | `raw_observation.geom` | 校验范围和两种表达一致性 |
| `altitude` | `height_amsl_m` | 来源定义为海拔；仍保留原始值 |
| `height` | `relative_height_m` | 不参与 AMSL 空间判定 |
| `distance` | `horizontal_distance_m` | 千米乘 1000 |
| `azimuth` | `azimuth_deg` | 站点到目标的方位角，不映射航向 |
| `elevation` | `elevation_deg` | -90 至 90 |
| `directSpeed` | `speed_mps` | 字符串或数值统一解析 |
| `freq` | `frequency_mhz` | MHz |
| `pilotGps` | `pilot_geom` | `lng/lat`，空字符串写 NULL |
| `model` | `model` | 厂商识别结果，不等同于平台设备型号 |
| `reason` | `end_reason` | `timeout` 映射为 `source_remove/timeout` 证据 |

## 9. 并发、幂等和乱序规则

1. 同一幂等键重复提交只返回已有观测 ID。
2. 会话更新使用行锁或按 `version` 做乐观并发控制。
3. 较旧观测可以追加到历史，但不能覆盖会话和航迹的当前观测。
4. 离线事件早于当前 `last_observed_at` 时，只保存为原始证据并标记 `stale_remove`，不关闭会话。
5. 无坐标观测不能清空已有当前位置。
6. 未知 `sourceType` 不能根据 `serial` 前缀自动改成电侦；后续同会话带类型消息可以更新会话的当前来源类型，但原始观测仍保持缺失事实。
7. 一个快照批次中单条失败不回滚其他合法条目；批次处理结果必须可审计。

## 10. 权限与安全

- 浏览器角色：只能读取 `api` 快照、增量、航迹和配置视图。
- 接入角色：只能执行侦测接入函数、更新指定设备状态，不得查询认证数据或修改业务配置。
- 管理角色：可维护设备资产和来源映射。
- `situation` 和 `equipment` 基础表不直接通过 PostgREST 暴露。
- 内部写接口使用独立服务令牌、TLS 和来源 IP 限制；不能复用前端管理员 JWT。
- 不接入文档中的 `/api/cloud/command/send`，不保存控制凭据。
- 原始载荷如未来包含手机号、Remote ID 或其他敏感标识，应增加字段分级和保留期限。

## 11. 保留与性能

第一阶段预计按 1 秒快照写入：

- `raw_observation` 和 `target_observation`：在线热数据保留 90 天，归档策略另行配置。
- `change_event`：保留 7 天。
- 空域目标、来源会话和航迹摘要长期保留。
- 高频航迹查询必须带时间范围和点数上限。

必要索引：

```text
equipment.raw_observation(asset_id, observed_at DESC)
situation.target_observation(observation_source_id, source_target_id, observation_id DESC)
situation.observation_source_status_current(last_message_at)
situation.source_target_session(state, last_observed_at)
situation.target_track(status, last_observed_at DESC)
situation.change_event(observation_source_id, id)
```

当目标观测稳定超过每月数千万条时，再按 `observed_at` 对原始观测和关联观测做月分区；第一阶段不提前引入分区复杂度。

## 12. 验收用例

1. 雷达消息 `sourceType=10` 入库后，快照显示“雷达”。
2. 电侦消息 `sourceType=20` 入库后，快照显示“电侦”。
3. 在线列表缺少 `sourceType` 时，保存观测并产生 `missing_source_type`，不错误推断。
4. 混合站点快照外层为 30、列表包含站点 90 时，站点 90 数据正确入库和查询。
5. 无 GPS 的电侦消息进入 `non_spatial_detections`，不在地图生成 `(0,0)` 点。
6. 同一消息重复提交两次，只产生一条原始观测和一条增量事件。
7. 乱序旧消息进入历史，但不覆盖最新位置。
8. 收到离线事件后航迹变为 `closed`，增量接口返回 `target_remove`。
9. 断开 WebSocket 后恢复，通过在线列表和增量游标完成对账，无重复航迹。
10. 不同来源的相同 `serial` 不会自动合并为同一目标。
11. `azimuth` 不会被误作目标航向参与入侵预测。
12. 所有空间判定只使用明确的 WGS84 坐标和 AMSL 高度；相对高度不直接参与判定。
