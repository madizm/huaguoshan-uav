# 云平台功放能力接入设计

## 1. 结论

将云平台功放作为 `equipment.asset.id=82` 的 `radio_jamming` 能力接入，但不能让浏览器直接调用厂商接口。

系统应使用“受控请求 + 持久化状态机 + 独立指令 worker + WebSocket 状态确认”的方式接入：

```text
操作端
  -> PostgREST 受控 RPC
  -> 功放操作记录 + 指令 outbox
  -> 功放指令 worker
  -> 云平台 HTTP /api/cloud/command/send

云平台 WebSocket /realTimeAlarmWebSocket
  -> 现有 radar_cloud_connector（按 type 分流）
  -> 功放实际状态 + 状态事件 + 操作状态机
  -> PostgREST 查询接口
  -> 操作端
```

两个开启方式统一为同一种设备能力下的两个控制模式：

- `omnidirectional_frequency`：按频段开启全向功放，对应厂商 `cmd=amp`。
- `target_coordinate`：按目标 WGS84 经纬度打击，对应厂商 `cmd=strike`。

全向频段模式必须有持久化关闭计划。目标坐标模式由 `strike.duration` 在设备侧计时关闭，不能使用 `amp action=0` 提前关闭。平台不得依赖浏览器计时器。业务请求的持续时间不得超过 60 秒；设备另有 120 秒硬保护。

## 3. 设备能力建模

### 3.1 能力字典

为资产 82 配置现有能力编码 `radio_jamming`，并将其接入级别设为 `controllable`。能力参数建议为：

```json
{
  "control_modes": [
    "omnidirectional_frequency",
    "target_coordinate"
  ],
  "omnidirectional_supported": true,
  "supported_frequencies_mhz": [2400, 5200, 5800],
  "max_operation_seconds": 60,
  "device_hard_protection_seconds": 120,
  "stop_strategy_by_mode": {
    "omnidirectional_frequency": "amp_action_0",
    "target_coordinate": "strike_duration"
  },
  "coordinate_system": "WGS84",
  "vendor_station_id": 90,
  "vendor_box_code": "b260705174118582"
}
```

厂商频率文本只由适配器生成。例如，平台 `2400` MHz 映射为厂商值 `2.4`。调用方不得直接传入厂商字符串。

### 3.2 控制级别约束

现有 `equipment.limit_sensitive_device_access()` 和旧版 `equipment.limit_counter_uas_access()` 会拒绝 `controllable`。迁移应将规则改为：

1. 敏感设备默认最高仍为 `recommendable`。
2. 仅白名单控制能力可以设为 `controllable`。
3. 当前白名单只包含资产 82 的 `radio_jamming`。
4. 白名单应使用专用授权表，不应把资产 ID 写入触发器函数。
5. 关闭授权后，新的开启请求立即被拒绝；关闭请求仍允许执行。

建议新增 `countermeasure.control_authorization`：

| 字段 | 说明 |
|---|---|
| `asset_id` | 获得控制授权的资产 |
| `capability_code` | 固定为已授权能力，如 `radio_jamming` |
| `enabled` | 是否允许新建开启操作 |
| `valid_from` / `valid_to` | 授权有效期 |
| `max_operation_seconds` | 单次上限，不得大于 60 |
| `allowed_modes` | 允许的控制模式 |
| `allowed_frequencies_mhz` | 允许使用的频率白名单 |
| `updated_by` / `updated_at` | 授权审计信息 |

## 4. 对内控制接口

### 4.1 开启功放

建议只提供一个深接口，用判别字段表达两种模式：

```http
POST /postgrest/rpc/start_amplifier_operation
Authorization: Bearer <countermeasure-operator-jwt>
Content-Type: application/json
```

全向频段模式：

```json
{
  "p_request": {
    "assetId": 82,
    "mode": "omnidirectional_frequency",
    "frequenciesMhz": [2400, 5200, 5800],
    "durationSeconds": 30,
    "reason": "人工确认的反制处置",
    "idempotencyKey": "ui-018f..."
  }
}
```

按目标坐标模式：

```json
{
  "p_request": {
    "assetId": 82,
    "mode": "target_coordinate",
    "frequenciesMhz": [2400, 5200, 5800],
    "durationSeconds": 30,
    "target": {
      "longitude": 119.196054,
      "latitude": 34.591989,
      "coordinateSystem": "WGS84",
      "observedAt": "2026-10-17T12:45:10Z",
      "trackId": 512
    },
    "reason": "人工确认的目标处置",
    "idempotencyKey": "ui-0190..."
  }
}
```

RPC 返回格式：

```json
{
  "operationId": "0190...",
  "assetId": 82,
  "state": "queued",
  "requestedDurationSeconds": 30,
  "requestedAt": "2026-10-17T12:45:14Z",
  "hardDeadlineAt": "2026-10-17T12:46:14Z"
}
```

数据库中的函数注释必须明确以上返回字段。

### 4.2 手动关闭

```http
POST /postgrest/rpc/stop_amplifier_operation
```

```json
{
  "p_asset_id": 82,
  "p_operation_id": "0190...",
  "p_reason": "操作员手动关闭",
  "p_idempotency_key": "ui-0191..."
}
```

关闭接口只适用于 `omnidirectional_frequency`，并且必须幂等。设备状态不明、开启操作缺失或授权已撤销时，接口仍应允许创建安全关闭指令。`target_coordinate` 由已下发的 `strike.duration` 到时关闭；厂商接口不支持提前关闭该模式，调用关闭接口时应返回明确的 `unsupported_operation_mode` 错误。

### 4.3 紧急关闭

提供仅限更高权限角色使用的 `emergency_stop_amplifier(p_asset_id, p_reason)`。该接口不依赖当前操作记录，直接为设备创建全频段 `amp action=0` 指令，并记录高优先级审计事件。该接口不能中止已经下发的 `strike`。

## 5. 开启条件与请求校验

### 5.1 设备状态门禁

开启操作只检查以下两个设备状态：

1. 盒子在线。
2. 处置子系统在线。

`unattended`、遥测新鲜度和当前功放状态不作为开启门禁。关闭请求不检查设备状态门禁。

### 5.2 接口数据校验

以下项目属于身份、能力和请求格式校验，不属于设备状态门禁：

1. 资产存在，并映射到唯一的 `radar_cloud` 站点和盒子。
2. 资产启用了可控制的 `radio_jamming` 能力。
3. 调用身份具有控制权限。
4. 同一资产没有冲突的非终态操作。
5. 持续时间在 `1..60` 秒内。
6. 频率只能是 `2400`、`5200`、`5800` MHz。
7. 全向模式要求设备支持全向功放。
8. 目标模式要求合法的 WGS84 经纬度。
9. 操作原因和幂等键非空。

关闭请求只执行资产映射、调用权限、模式和请求格式校验。

## 6. 厂商指令适配

### 6.1 全向频段模式

平台规范请求：

```json
{
  "mode": "omnidirectional_frequency",
  "frequenciesMhz": [2400, 5200, 5800]
}
```

适配为：

```json
{
  "stationId": 90,
  "boxCode": "b260705174118582",
  "cmd": "amp",
  "data": {
    "action": 1,
    "freqs": "2.4,5.2,5.8"
  }
}
```

### 6.2 目标坐标模式

平台规范请求适配为：

```json
{
  "stationId": 90,
  "boxCode": "b260705174118582",
  "cmd": "strike",
  "data": {
    "gps": "119.196054/34.591989",
    "duration": 30,
    "freqs": "2.4,5.2,5.8"
  }
}
```

### 6.3 全向频段模式关闭

协议明确给出的关闭命令是：

```json
{
  "stationId": 90,
  "boxCode": "b260705174118582",
  "cmd": "amp",
  "data": {
    "action": 0,
    "freqs": "2.4,5.2,5.8"
  }
}
```

关闭时应使用操作记录中的频率，并可在紧急关闭时发送设备全部支持频率。该命令不能关闭 `strike`；目标坐标模式只能等待 `strike.duration` 到期。

### 6.4 HTTP 响应

厂商成功响应的 HTTP 状态码为 `200`，响应体为：

```json
{
  "status": 200,
  "msg": "指令已下发",
  "data": null,
  "serverErrorMsg": null
}
```

worker 仅在 HTTP 状态码和响应体 `status` 都为 `200` 时记录 `dispatched`。该响应表示指令已下发，不能替代 WebSocket 的设备状态确认。

## 7. 状态接入与确认

现有 WebSocket 地址保持不变：

```text
ws://{edge-host}:8003/realTimeAlarmWebSocket
```

扩展 `scripts/radar_cloud_connector.py` 的消息类型路由：

```text
uav_*            -> 目标侦测处理
config_status    -> 设备遥测处理
uav_amp_status   -> 功放状态处理
未知 type        -> 忽略并计数
```

`uav_amp_status` 规范化字段：

| 厂商字段 | 平台字段 | 规则 |
|---|---|---|
| `deviceSn` | `source_asset_id` | 映射到资产，不信任前端传值 |
| `stationId` | `station_id` | 必须匹配已配置来源 |
| `ampStatus` | `actual_state` | `1=on`，`0=off`，其他值拒绝 |
| `freq` | `active_frequencies_mhz` | 转为 MHz 数组 |
| `unattendedType` | `trigger_source` | `0=manual`，`1=unattended` |
| `serial` | `source_target_id` | 可空，不用于资产映射 |
| `durationSec` | `vendor_duration_seconds` | 可空，校验范围 |
| `time` | `observed_at` | 毫秒时间戳；异常时标记质量问题 |
| 接收时间 | `received_at` | 连接器本机 UTC 时间 |

建议新增：

- `countermeasure.amplifier_state_current`：每个资产的当前实际状态。
- `countermeasure.amplifier_status_event`：追加式保存每条功放开关事件。
- `countermeasure.amplifier_operation`：保存用户意图和操作生命周期。
- `countermeasure.command_outbox`：保存待发送和重试的厂商指令。
- `countermeasure.operation_event`：追加式保存状态变化和审计信息。

状态确认规则：

1. `uav_amp_status` 是开启和关闭确认的主要来源。
2. `config_status.freqsOn` 是每 2 秒一次的对账来源。
3. HTTP 响应不能直接把操作标记为 `active` 或 `stopped`。
4. WebSocket 断开时，当前实际状态改为 `unknown`，不能改为 `off`。
5. WebSocket 重连后必须补发当前功放状态；连接器在收到补发状态前保持 `unknown`。
6. 乱序事件可以写入历史，但不能覆盖更新的当前状态。
7. 未匹配到本平台操作的开启事件仍要入库，并触发“外部开启”告警。

由于厂商事件没有平台指令 ID，只能用资产、频率、发送时间窗口和目标序列号做弱关联。操作记录必须保留 `correlation_quality=exact|time_window|unmatched`，不能伪造精确关联。

## 8. 操作状态机

```text
queued
  -> dispatching
  -> awaiting_on_confirmation
  -> active

omnidirectional_frequency:
  active -> stop_queued -> awaiting_off_confirmation -> stopped

target_coordinate:
  active -> awaiting_duration_expiry -> stopped

任意非终态 -> failed
任意已发送状态 -> unknown
```

关键规则：

- 同一资产最多有一个非终态开启操作。
- `idempotencyKey` 重复时返回原操作。
- 收到 `ampStatus=1` 后才进入 `active`。
- 收到 `ampStatus=0` 或可靠的 `freqsOn` 空状态后才进入 `stopped`。
- 全向模式未收到开启确认时，也必须按保守截止时间发送 `amp action=0`。
- 全向模式未收到关闭确认时持续重试，并将实际状态显示为 `unknown`。
- 目标模式使用已下发的 `strike.duration`，平台不创建 `amp action=0` 关闭指令。
- 目标模式到期后等待 WebSocket 关闭事件；未收到时将实际状态显示为 `unknown`。
- worker 重启后必须扫描所有非终态操作并恢复计时。

## 9. 60 秒安全约束

### 9.1 不能依赖的机制

以下机制都不能单独满足 60 秒约束：

- 浏览器 `setTimeout`。
- 用户手动点击关闭。
- HTTP 开启请求的返回结果。
- 单个进程内的内存计时器。
- 仅在收到 `uav_amp_status` 后才建立关闭计划。

### 9.2 平台侧保护

开启请求入库时同时写入持久化的最晚领取时间，防止旧请求迟到执行。全向模式还立即写入 60 秒业务截止时间；目标模式在厂商接受后，按实际下发的 `strike.duration` 计算预期结束时间。worker 应按模式执行：

全向频段模式：

1. 发送开启指令前写 `start_dispatched_at`。
2. 在发送开启 HTTP 请求前创建关闭 outbox，不等待开启确认。
3. 用户时长到期时发送第一次 `amp action=0`。
4. 关闭未确认时按短间隔重试。
5. 到达 60 秒业务截止时提升为紧急关闭并告警。
6. worker 恢复后优先处理全部逾期操作。

目标坐标模式：

1. 将 `1..60` 秒写入 `strike.duration`。
2. 不创建 `amp action=0` 关闭 outbox。
3. 到期后等待 WebSocket 补发或推送关闭状态。
4. 超过确认宽限仍未关闭时，将状态标为 `unknown` 并告警。

全向模式建议最多选择 55 秒，预留 5 秒发送关闭指令。目标模式可以使用最多 60 秒，因为设备按 `strike.duration` 自行计时。

### 9.3 无法由平台单独保证的情况

设备提供 120 秒硬保护。该保护可以避免功放无限开启，但不能单独满足业务要求的 60 秒上限。

- 全向模式依赖平台在 60 秒内发送 `amp action=0`。如果平台、网络和设备通信同时失效，实际开启可能持续到设备的 120 秒硬保护。
- 目标模式由 `strike.duration` 在设备侧计时关闭。平台将该参数限制为最多 60 秒。

如果全向模式的 60 秒上限是不可突破的安全约束，还需要设备侧增加 60 秒保护，或在边缘侧部署独立 watchdog。系统不得把 120 秒硬保护描述成满足 60 秒要求。

## 10. 并发、幂等与事务

- 使用部分唯一索引限制每个资产只有一个非终态操作。
- 开启 RPC 在一个事务内写操作记录和开启 outbox。
- worker 使用 `FOR UPDATE SKIP LOCKED` 领取 outbox。
- 每条 outbox 使用稳定的幂等键。
- 厂商接口没有幂等契约时，开启指令不能无界重试。
- 关闭指令可以安全地按有限间隔重试。
- 任何失败都不能删除操作、outbox 或状态事件。
- 所有截止时间使用数据库 `timestamptz` 和数据库时钟。

## 11. 权限与审计

云平台功放控制不设置额外的浏览器业务角色。当前认证模型中的登录用户使用 `admin` JWT，因此任一已登录用户都可以查询状态、开启功放、关闭全向模式和执行紧急关闭。匿名用户不能查询或控制。

机器身份仍按最小权限隔离：

- `countermeasure_worker`：只领取 outbox、写发送结果和推进截止任务。
- 现有 `detection_ingest`：只写 WebSocket 状态，不能创建指令。

每次操作至少记录：

- 操作人 JWT `sub` 和用户名快照。
- 资产、模式、频率、目标坐标和目标观测时间。
- 业务原因。
- 请求时间、发送时间、确认时间和关闭时间。
- 原始厂商请求和脱敏响应。
- WebSocket 确认事件。
- 手动关闭、超时关闭或紧急关闭原因。
- 每次状态迁移和错误码。

不得在表中保存厂商密钥。当前协议标注无鉴权，生产网络仍应限制目标地址、来源 IP 和出站权限。

{
  "asset_id": 82,

## 13. 前端交互

资产 82 的功放操作区只使用以下设备状态门禁：

- 盒子在线。
- 处置子系统在线。

身份、能力、并发、时长、频率和坐标仍由控制 RPC 校验，但不属于设备状态门禁。

交互要求：

1. 先选择“全向频段”或“目标坐标”。
2. 全向模式只展示设备允许频率。
3. 目标模式输入 WGS84 经纬度；如果从当前目标带入，则同时显示并提交航迹和观测时间。
4. 操作员输入原因并二次确认。
5. 开启后持续显示倒计时、请求状态和实际状态。
6. 全向模式显示“关闭”按钮；目标模式明确显示“到时自动结束，不能提前关闭”。
7. 页面关闭或刷新不影响全向模式的关闭计划，也不影响已下发的 `strike.duration`。
8. WebSocket 重连后等待补发状态，再刷新实际状态展示。

## 14. 已确认的厂商约定与剩余问题

已确认：

1. `amp action=0` 不能关闭 `strike`。
2. `strike` 使用独立的 `duration` 参数在设备侧计时结束。
3. 设备具有 120 秒硬保护。
4. `strike.gps` 使用 WGS84 坐标。
5. 指令成功时 HTTP 状态码为 `200`，响应体 `status=200`、`msg=指令已下发`。
6. WebSocket 重连后必须补发当前功放状态。
7. 支持频段固定为 2.4G、5.2G、5.8G。

仍需在联调中验证：

1. `amp` 重复开启、重复关闭和部分频段关闭是否幂等。
2. 同一盒子收到并发 `amp` 与 `strike` 时的行为。
3. `uav_amp_status.time` 的时区、时钟精度和乱序行为。
4. 手动操作时 `serial` 的真实空值形式。
5. HTTP 成功但设备未执行时，是否必定产生状态事件。
6. WebSocket 重连补发的事件类型、时序和完整字段。

120 秒硬保护不能证明全向模式满足 60 秒上限。该风险需要业务确认或新增边缘保护。

## 15. 实施拆分

### 第一阶段：只读状态接入

1. 扩展 WebSocket 路由以接收 `uav_amp_status`。
2. 增加当前状态和追加事件表。
3. 用 `config_status.freqsOn` 做周期对账，并验证重连后的状态补发。
4. 增加只读 PostgREST 资源和后台展示。
5. 验证厂商事件字段、频率单位和乱序行为。

### 第二阶段：受控关闭

1. 增加控制授权、操作表和 outbox。
2. 实现指令 worker。
3. 先只开放全向模式的紧急关闭和人工关闭。
4. 验证重复关闭、断线关闭和状态确认。

### 第三阶段：短时开启

1. 开放 `omnidirectional_frequency`。
2. 初期把时长限制为 5 秒。
3. 完成 24 小时故障注入和审计验证。
4. 验证 120 秒硬保护和平台关闭时序后，逐步提高到最多 55 秒。

### 第四阶段：目标坐标模式

1. 按已确认的 WGS84 坐标构造 `strike.gps`。
2. 支持手工输入 WGS84 经纬度；目标航迹与目标观测时间作为可选关联信息。
3. 验证 WGS84 坐标传递和 60 秒内的设备侧计时关闭。
4. 验证 `strike.duration` 到期和 WebSocket 关闭事件后开放。

## 16. 验收用例

1. 无 `radio_jamming` 可控能力时拒绝开启。
2. 非全向设备拒绝全向频段模式。
3. 盒子离线或处置子系统离线时拒绝开启。
4. `unattended` 和遥测新鲜度不阻止开启。
5. 2.4G、5.2G、5.8G 之外的频率被拒绝。
6. 非 WGS84 或非法目标坐标被拒绝。
7. 同一幂等键只创建一个操作。
8. 同一资产不能并发开启两次。
9. HTTP 200 且响应体 `status=200` 时只标记为已下发。
10. HTTP 成功但无 WebSocket 确认时不显示为已开启。
11. 收到 `uav_amp_status=1` 后显示实际开启。
12. 全向模式手动关闭后持续等待 `ampStatus=0` 确认。
13. `amp action=0` 不用于关闭目标模式。
14. 目标模式把 60 秒写入 `strike.duration`，到期后等待关闭状态。
15. 页面关闭后，worker 仍按时发送全向模式关闭指令。
16. worker 重启后恢复全向模式逾期关闭任务。
17. WebSocket 断开时状态变为未知，重连后等待补发状态。
18. 外部平台直接开启功放时生成未匹配操作告警。
19. 55 秒全向操作在 60 秒业务截止前发出关闭指令。
20. 全向关闭未确认时自动重试并触发告警。
21. 操作人、原因、目标、请求、响应和状态事件均可审计。
22. 普通管理员和接入角色不能开启功放。
