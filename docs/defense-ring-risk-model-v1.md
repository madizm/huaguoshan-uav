# 防御圈风险研判：第一阶段数据设计与默认值

> 状态（2026-09-25）：防御圈及评分配置、Python 实时风险 worker、版本化评估历史/current 投影和态势查询风险属性已实现。正式空域事件的连续确认、升级/降级迟滞和自动生成仍未接入；风险引擎不触发真实设备动作。数据库接口及当前管理能力见 [`api/defense-ring-admin-api.md`](./api/defense-ring-admin-api.md) 和 [`api/target-risk-assessment-engine.md`](./api/target-risk-assessment-engine.md)。适用场景为侦测到的**空域目标**，不假定每个目标都是无人机。

## 1. 范围与约定

- 以防御圈作为此场景唯一的空间范围来源；`airspace.no_fly_zone`、`airspace.temp_control_zone` 不参与新的风险研判。圈层是空间事实，不是风险等级。
- 防御圈是**二维圆形范围**：以保护对象 WGS84 中心点和半径（米）定义；不配置高度上下限或高度基准。目标高度缺失不影响圈层判定；高度若存在仍可作为观测证据展示，但不参与本模型评分或空间过滤。
- 每条目标航迹、每个研判时刻**至多选中一个**生效且水平命中的防御圈：`priority DESC, ring_level DESC, id ASC`。不同保护对象的圈也按同一规则竞争。记录选中圈、配置版本与排序依据，不将多个命中圈分数叠加。
- 第一阶段仅对有有效 WGS84 位置和可信观测时间的航迹进行自动判定。无坐标、过期或冲突观测标记为 `insufficient_data`，不得判为“圈外正常”。没有命中且数据充分时为 `outside`。
- 圈外是判定结果，不建无限大的圈。第一阶段仅在命中防御圈后建立候选事件；圈外接近的提前告警是后续扩展，不以“最近保护对象”擅自代替命中规则。
- GGER 网格可作粗筛与展示，精确判断仍以 PostGIS **米制地理距离**为准，不能对经纬度直接按度数比较半径。保留目标原始观测、航迹和规则快照以支持回放。正式风险等级属于空域事件；候选阶段的分数是临时研判结果，不伪装成正式事件。

## 2. 建议表结构

以下为配置与目标风险研判的逻辑结构。防御圈、保护对象、评分配置、追加式目标评估历史和 current 投影已创建；正式空域事件及其确认/迟滞状态机仍为设计，部署状态以实际迁移为准。实施遵循 `api` schema、权限及中文注释规范。

| 表 | 字段/约束 | 说明 |
| --- | --- | --- |
| `airspace.protected_object` | `id PK`, `name`, `geom geometry(Point,4326)`, `enabled`, `created_at`, `updated_at` | 保护对象及接近速度的参考点；保护对象不等于侦测目标。 |
| `airspace.defense_ring` | `id PK`, `protected_object_id FK`, `code`, `version > 0`, `name`, `center_geom geometry(Point,4326)`, `radius_m numeric > 0`, `ring_level 1..5`, `priority integer`, `valid_from`, `valid_to`, `enabled`, `created_at` | `(code, version)` 唯一；发布时将保护对象中心位置固化在圈版本中，已引用版本不可修改/删除；有效期起点 < 终点（若有）。不存独立 Polygon，也不设高度字段。`center_geom` 建 GiST 索引，按圈生效状态/时间建检索索引。 |
| `event_response.risk_rule_set` | `id PK`, `code`, `version > 0`, `status draft/active/retired`, `effective_from`, `effective_to`, `created_at` | `(code, version)` 唯一；同一规则编码任一时刻至多一个生效版本。发布后冻结，调参发布新版本。 |
| `event_response.risk_rule_factor` | `id PK`, `rule_set_id FK`, `factor_code`, `condition_code`, `threshold_value`, `unit`, `score integer`, `exclusive_group`, `enabled` | 一项一行，规则编码和条件编码为受控枚举，不能把任意 SQL/表达式作为配置执行；同组阈值只取一个最高适用档。 |
| `event_response.risk_rule_parameter` | `rule_set_id FK`, `parameter_code`, `value_numeric`, `unit`，联合 PK | 等级分界、数据窗口及状态迟滞参数；用受控编码并按参数校验单位/范围。 |

不要同时在 `defense_ring` 和规则表维护两份基础分；基础分由 `ring_level` 对应的因子定义。同一保护对象在同一生效时段各圈必须共用同一版本中心点，且满足 `核心圈 < 硬打击圈 < 反制圈 < 跟踪圈 < 感知圈` 的半径顺序，每层最多一个有效版本；中心迁移应同步发布该对象的整组圈版本。不同保护对象允许配置不同中心、半径和优先级，但本版本暂不支持各对象私有评分权重。`priority` 只用于重叠选择，**不同于处置优先级**。

判定示意：`ST_DWithin(defense_ring.center_geom::geography, observation.geom::geography, defense_ring.radius_m)`。圆边界由版本固化的中心和半径派生，Cesium 展示可生成近似多边形，但展示几何不是判定真值；中心或半径变化应发布新配置版本，不原地改写历史。大量圈查询时按表达式 `(center_geom::geography)` 建 GiST 索引并检查执行计划；跨对象重叠仍按全局优先级择一。

读写边界：后台配置通过受控 `api` 视图/RPC；研判进程读取已发布配置；候选事件引用 `track_id`、所选 `defense_ring.id` 和规则集版本；正式事件的追加式 `event_response.risk_assessment` 记录 `rule_set_id/version`、选中圈 `id/code/version`、观测 ID、分数、因子取值与解释。不要把实时窗口点复制为第二套原始轨迹。

## 3. 默认试运行配置 `defense-risk-v1`

默认圈层及半径按本系统业务约定；基础分和优先级是待回放验证的**试运行初始值**，不是实测校准结论。半径可按保护对象配置，必须满足嵌套顺序；核心圈须高于与之重叠的外围圈。保护对象真实坐标须由业务提供，**不预置虚构坐标**。

| 圈层 | `ring_level` | 默认半径（米） | 建议 `priority` | 试运行基础分 |
| --- | ---: | ---: | ---: | ---: |
| 圈外 | 0（非表记录） | — | — | 0 |
| 感知圈 | 1 | 5000 | 100 | 20 |
| 跟踪圈 | 2 | 4000 | 200 | 35 |
| 反制圈 | 3 | 3000 | 300 | 50 |
| 硬打击圈 | 4 | 2000 | 400 | 70 |
| 核心圈 | 5 | 1000 | 500 | 85 |

圈名仅表示研判中的空间层级。“反制圈”“硬打击圈”**不是**设备能力覆盖范围、实际反制权限或自动执行命令；平台仍只做研判、建议与模拟联动，不因命中圈层触发真实设备动作。

建议稳定 `code` 依次为 `sensing`、`tracking`、`countermeasure`、`hard_strike`、`core`；显示名称可本地化，计算只使用编码和 `ring_level`。各圈是同心的包含范围，目标同时落在多层半径内时依优先级选择最内层，而不是将各层基础分相加。

| 因子 | 条件（仅数据充分时） | 分数 |
| --- | --- | ---: |
| `continuous_approach` | 最近 ≥10 秒且 ≥4 个有效位置，向选中圈版本的中心点平均接近速度 ≥2 m/s | +10 |
| `fast_approach` | 已满足持续接近，平均接近速度 ≥10 m/s | +5 |
| `next_ring_eta_60` | 航向可靠、沿预测短航迹将于 30～60 秒进入同一保护对象的更深一圈 | +10 |
| `next_ring_eta_30` | 同上，ETA ≤30 秒 | +20 |
| `identity_unverified` | 身份状态为 `unverified` | +5 |

ETA 两档属同一个 `exclusive_group`，仅取最高适用分。沿短期运动方向预测**首次与下一圈半径边界的交点**，而不是仅用距中心距离除以接近速度；若没有更深一圈、预计航迹不相交、航向不稳定或位置质量不足，则 ETA 为“不可用”，不加分，也不显示虚假的秒数。ETA 使用实际观测时间差，不假设恒定 2 秒采样。`score = clamp(基础分 + 适用附加分, 0, 100)`；评分时保留未适用/不可评估的区别。盘旋、折返、停留、黑名单和白名单不在 v1 自动计分：授权飞行应另行验证身份、任务、时空范围，不使用“白名单 -80 分”。

| 分数区间 | 判定 | 正式事件风险等级 |
| --- | --- | --- |
| 0–19 | 正常 | 不形成事件 |
| 20–39 | 低 | `low` |
| 40–59 | 中 | `medium` |
| 60–79 | 高 | `high` |
| 80–100 | 严重 | `critical` |

默认确认/迟滞：单次有效命中生成**候选事件**，连续 2 个有效观测命中所选圈才确认为正式事件；等级升级连续 2 个有效观测达到新等级，降级连续 5 个有效观测达到低等级且离开原圈 ≥10 秒。丢点、重复、乱序及 `insufficient_data` 不计入连续次数；目标会话结束时停止研判，不把失联视为已离圈。首次进入核心圈或其他紧急情形是否允许跳过确认窗口，需另定有证据的例外规则，本版本不默认绕过。

## 4. 发布前验收与迁移

- 回放：半径边界抖动、重叠保护对象、相同优先级、缺坐标、缺高度、异常时间戳、快速远离、横穿、丢点与身份冲突；验证缺高度仍可判圈，结果唯一且可复现。
- 发布规则、防御圈或保护对象中心点新版本时，历史研判保持所用圈版本中的中心、半径、规则版本及因子快照，不能用新半径或中心重写旧结论。
- 逐一盘点旧 `no_fly_zone`/`temp_control_zone` 的接口、航线规划、前端和文档引用；**仅新研判停止依赖旧表**，待其他使用方迁移后再停用接口/删表。原有共享事件工作台保留，场景扩展记录改为引用防御圈。
- 架构第一阶段采用已有 PostGIS/PostgREST、侦测航迹和按游标增量；Redis/MQTT/独立推送服务在实际容量或时延要求验证后再引入。
